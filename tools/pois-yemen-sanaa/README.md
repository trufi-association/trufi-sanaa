# pois-yemen-sanaa

Generates the Sana'a POI files (`assets/pois/*.geojson` + `metadata.json`) with
[`trufi-association/trufi-server-poi_extractor`](https://github.com/trufi-association/trufi-server-poi_extractor)
used as a Node library — no fork, no submodule. The pinned commit lives in
[`package.json`](package.json).

The same files feed two features of the app: the map's POI layers
(`trufi_core_poi_layers` reads `metadata.json` and one GeoJSON per category)
and the offline place search (`OfflinePoiSearchService` indexes every
category listed in `poiAssetPaths`, `lib/main.dart`).

## Run

```bash
npm install
npm start
rm ../../assets/pois/*.geojson
cp out/*.geojson out/metadata.json ../../assets/pois/
python3 ../pois-enrich-latin.py   # adds name:latin to Arabic-only names
```

`npm start` prints the POI count per category and subcategory; compare it
with the previous `metadata.json` before committing.

## Input

Reads `../pbf-yemen-sanaa/out/sanaa.osm.pbf` (generated by the sibling tool).
If it isn't there, run that tool first.

## Categories

[`categories.json`](categories.json) is the extractor's default category set
plus what the Sana'a community actually maps (issue #17: places present in
OSM were missing from the search because their tags were outside the
defaults):

| Category | Added for Sana'a |
| --- | --- |
| healthcare | `nursing_home`, `social_facility`; opticians and medical supply shops |
| education | `institute` (`office=educational_institution`, driving/language schools, research); `building=school/college/university` |
| transport | `fuel` (`amenity=fuel`, `charging_station`) |
| shopping | `fashion`, `electronics`, `home`, `vehicles` (incl. `car_repair`, `car_wash`), `stationery`, `beauty` (hairdressers), `laundry`, `travel` (agencies, also `office=travel_agent`), more `food_shop` values and `other_shop` = every remaining `shop=*` |
| tourism | `tourism=chalet`, `apartment` as accommodation |
| recreation | `events_venue` (wedding halls), `arts_centre`, pitches and clubs, `wellness` (hammams) |
| religion | `cemetery` (`amenity=grave_yard`, `landuse=cemetery`) |
| government | `office=diplomatic` as embassies, `prison`, `organizations` (`office=ngo/foundation/association/…`) |
| services (new) | `telecom` (incl. internet cafés), `industry` (`man_made=works`), `crafts` = every `craft=*`, `company` = every remaining `office=*` |

Order matters: the extractor assigns a POI to the first category and
subcategory whose matcher hits, so the specific sets come first and the
`shop=*` / `office=*` / `craft=*` catch-alls last. That is also why the
`shop=*`-tagged services (hairdressers, laundries, travel agencies) sit in
`shopping` rather than in `services`: `shopping` comes first and its
`other_shop` catch-all would otherwise take them. Street furniture that is
not a place people search for (`amenity=parking`, `toilets`, `drinking_water`,
`waste_disposal`, `post_box`, `telephone` boxes) is left out on purpose.

Each `displayName` carries `en`/`es`/`de` (what the extractor's type
declares) plus `ar`; the Arabic label is copied into `metadata.json` as
`displayName:ar` by [`extract.mjs`](extract.mjs), and the app shows it in the
Arabic UI.

## Icons

`icons/maki/` holds the [Maki](https://github.com/mapbox/maki) icons the
categories reference (CC0 1.0): the set the extractor ships, plus `fuel`,
`clothing-store`, `mobile-phone`, `furniture`, `car-repair`, `hot-spring`,
`cemetery`, `hairdresser`, `laundry`, `suitcase`, `telephone`, `industry`,
`hardware` and `commercial`, downloaded from
`https://raw.githubusercontent.com/mapbox/maki/main/icons-meta/<name>.svg`.
They have to live here because the npm package does not include the
extractor's `icons/` folder. `npm start` reports `missing: 0` when every
referenced icon was found.

## Why not `poi-extractor -c categories.json`

The CLI's `-c` option is broken in the pinned version: `loadCategories()`
calls `require('fs')` from an ES module, the `ReferenceError` is swallowed
and the run silently continues with the defaults (it prints
`Warning: Could not load custom categories … using defaults`). The script
passes the categories through the library API instead.
