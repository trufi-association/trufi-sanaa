# search-yemen-sanaa

Generates the Sana'a offline search index using
[`trufi-association/osm-search-data-export`](https://github.com/trufi-association/osm-search-data-export)
as a Node library. The app bundles the output as `assets/search/search.json`,
where trufi-core's `OfflineSearchDataService` reads it to answer street and
street-corner queries offline ("شارع تعز و شارع حدة"), next to the POI search
(`OfflinePoiSearchService`) in a `CompositeSearchLocationService`. The corners
are also what "Lines along `<street>`" is built on (trufi-core#1051, issue #20):
the first row of a street's corners list opens the nearby-lines screen over
every corner of the street.

## Run

```bash
npm ci               # Node >= 22.12 (require(esm): decode-uri-component is ESM-only; better-sqlite3 13 ships prebuilt binaries)
npm start
cp out/search.json ../../assets/search/search.json
```

The exporter is pinned to a GitHub tag (`github:trufi-association/osm-search-data-export#v1.2.0`);
bump the tag in `package.json` to pick up a new version.

Output: `./out/search.json` (not committed: `out/` is ignored — the copy under
`assets/search/` is the one the app ships and the only one tracked, so a
refresh is a one-file diff). Contains `streets` and `streetJunctions` keyed for
prefix search — `pois` is stripped on purpose (the app's places come from the
POI GeoJSON of `tools/pois-yemen-sanaa`); only the empty `pois` key and its
`_fields` header remain, which `OfflineSearchDataService` ignores.

What the first run (2026-10-30) produced from the committed PBF: 206 streets
(193 named in Arabic), 176 of them with corners, 614 corner rows; the names
are the OSM `name` tags as written (`alternativeNames` carries `alt_name`
and the like, not `name:en`, so a street is found by its Arabic name).
`index.js` drops the ways whose `name` has no letter at all (the extract has
three: ".", "3180", "801" — they ranked first for any query starting with a
digit) and strips the U+200E/U+200F marks pasted inside a name; the run
prints what it dropped.
`region` (the municipality) is empty: the extract has no `admin_level=8`
boundaries, so the street rows have no subtitle. Sana'a's OSM data names
few of its streets (18 142 highway ways in the extract, 1 142 with a
`name`, 243 distinct spellings); more names in OSM mean more streets here
on the next run.

## Input

Reads `../pbf-yemen-sanaa/out/sanaa.osm.pbf` (committed; generated by the
sibling tool). If it isn't there, run that tool first.

## After a PBF refresh

The app bundles four snapshots derived from this PBF, and they have to come
from the same file: the GTFS feed (`../gtfs-yemen-sanaa` → `assets/routing/`),
the POI layers (`../pois-yemen-sanaa` → `assets/pois/`), the offline map tiles
(`../mbtiles-yemen-sanaa` → `assets/offline/sanaa.mbtiles`) and this index
(→ `assets/search/`). Whenever `../pbf-yemen-sanaa` is re-run, regenerate the
four together and commit them in the same change: a refresh that skips this
tool leaves new streets routable but unsearchable.
